# ХанБио CRM

Веб-панель администратора реабилитационного центра: заявки из бота, записи к
инструктору, записи в общий зал, карточки клиентов.

**Стек:** Next.js 15 (App Router) · Supabase (Postgres + Auth) · Tailwind v4 ·
деплой на Vercel.

Общая база с Telegram-ботом (`../bot`): бот пишет заявки и записи в тот же
Postgres, CRM их читает и обрабатывает.

---

## 1. Supabase

1. [supabase.com](https://supabase.com) → **New project** (регион поближе, напр.
   `Central EU (Frankfurt)`). Запомни пароль БД.
2. **SQL Editor** → New query → вставь целиком
   [`supabase/migrations/0001_init.sql`](supabase/migrations/0001_init.sql) →
   **Run**. Создаст все таблицы (бота + CRM) и политики RLS.
3. **Authentication → Users → Add user** → заведи аккаунт(ы) администраторов
   (email + пароль, «Auto Confirm User»).
4. **Project Settings → API** — понадобятся:
   - `Project URL` → `NEXT_PUBLIC_SUPABASE_URL`
   - `anon public` key → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `service_role` key → `SUPABASE_SERVICE_ROLE_KEY` (секрет, только сервер)

---

## 2. Локальный запуск

```bash
cd crm
cp .env.example .env.local        # заполнить 3 значения из шага 1.4
npm install
npm run dev                       # http://localhost:3000
```

---

## 3. Деплой на Vercel

1. Запушь репозиторий на GitHub.
2. Vercel → **Add New → Project** → импорт репозитория.
3. **Root Directory** → `crm` (важно — приложение в подпапке).
4. **Environment Variables** → добавь `NEXT_PUBLIC_SUPABASE_URL`,
   `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`.
5. **Deploy**. Дальше каждый push в основную ветку деплоится автоматически.

---

## 4. Подключение бота к той же базе (когда будешь готов)

Сейчас бот пишет в локальный SQLite. Чтобы данные пошли в Supabase и появились
в CRM:

1. Supabase → **Project Settings → Database → Connection string → URI**,
   режим **Session pooler** (порт 5432, не Transaction).
2. В `../.env` бота заменить:
   ```
   DATABASE_URL=postgresql+asyncpg://postgres.<ref>:<пароль>@<host>:5432/postgres
   ```
   (префикс именно `postgresql+asyncpg://`).
3. `pip install -r ../requirements.txt` (добавлен `asyncpg`).
4. Перезапустить бота. Схема уже создана SQL-файлом из шага 1 — Alembic на
   Postgres не запускается (бот это определяет сам).

Существующие записи из SQLite при этом не переносятся — только новые пойдут в
общую базу. Если нужен перенос старых — скажи.

## Экраны

| Раздел | Что делает |
|--------|-----------|
| **Дашборд** | счётчики: новых заявок, за сегодня, необработанных записей к инструктору, записей в зал впереди; последние заявки |
| **Заявки** | все обращения из бота (сценарии 3–9 + обострение); вкладки Новые/Обработанные/Все; раскрытие деталей, комментарий, отметка «обработано» |
| **К инструктору** | как лист «Запись к Инструктору Новая»: дата, время, ФИО, инструктор, телефон, возраст, статус, программы; редактируются инструктор / возраст / статус / программы |
| **Общий зал** | предстоящие записи из таблицы расписания, сгруппированы по дню и слоту |
| **Клиенты** | группировка по телефону; карточка — вся история записей и заявок |
